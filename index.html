    Where prices and stock come from, live

    1. Simplest: a shared Google Sheet or Excel file the office already edits (product, price per ton, stock). The chat reads it every few minutes.
    2. Better: a nightly or hourly sync from ABC’s POS, scale-house or inventory system (export or API), so stock drops when tickets are written.
    3. Always: a small owner page like the one above for quick overrides, such as “Sedona Red is low” or “holiday delivery rates.”

    The file this preview uses is abc-data.json: price per ton (pickup), delivery fee by zone, and stock status (In stock / Low / Out / Seasonal) for every product. All values are examples.

    How the live version stays safe

    Honest about this preview

    This preview is rule-based: there’s no AI model behind it. It matches questions to ABC’s published info, and everything runs in your browser. The live version would add a real AI model, with these guardrails:

    • A mainstream model behind a small server. For example GPT-4o-mini, Claude Haiku or Gemini Flash, called through a small server proxy. No API key ever sits in the browser.
    • Grounded answers. Answers come from ABC’s own catalog, prices and stock through retrieval. When the answer isn’t there, it hands off to (602) 272-1792 instead of guessing.
    • Math done by code, not the model. Prices, delivery fees and tonnage are calculated by code, never by the model.
    • Prompt-injection defenses. Customer text is treated as data, the topic is locked to ABC, the system prompt stays private, and nothing happens without approval (no discounts, orders or refunds).
    • Moderation in English and Spanish. Input and output are checked (e.g. OpenAI Moderation or Llama Guard).
    • Rate limits, logs and testing. Rate limits stop abuse, conversation logs are kept for ABC to review, and a red-team test set runs before every release.
